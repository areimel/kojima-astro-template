A situation-room handoff should let the next reviewer understand what changed without reconstructing the entire investigation. This fictional exercise uses a possible logistics delay to demonstrate a compact briefing structure.

## Lead with the change

Start with the new observation: “A synthetic terminal notice now overlaps the planned handling window for the sample shipment.”

Include the event time and the time the record entered the review. A late-arriving update should not appear to be a new event simply because it was added recently.

## State the business question

The question in this exercise is whether the delivery plan needs an alternate route review. Keep the affected dependency beside that question so the reader can see why the signal matters.

Avoid expanding the brief into an unsupported assessment of an entire region.

## Use a repeatable structure

1. **Observation:** What the source explicitly reports.
2. **Assessment:** What that may mean for the sample dependency.
3. **Evidence:** The records supporting the assessment.
4. **Uncertainty:** Missing context and alternative explanations.
5. **Follow-up:** A review task, an assigned role, and a revisit condition.

These fields describe an editorial pattern. They are not a claim that the template implements task assignment or a briefing workflow.

## Make the next review conditional

The sample handoff requests a review when the terminal assignment is confirmed or the handling estimate changes. If neither arrives by the next planned checkpoint, the uncertainty remains visible.

“Nothing new received” is different from “no disruption.” The briefing should preserve that distinction.

## Retain the earlier reasoning

When the view changes, a production workflow would need a way to retain the previous assessment and explain the revision. This demo illustrates the content of that explanation; it does not provide an audit-history or records-retention service.
