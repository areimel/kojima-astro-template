A synthetic exercise can reveal whether an intelligence interface helps a team reason clearly. It needs a decision to support, a small evidence set, and enough ambiguity to test the review process.

This note describes a fictional Kojima walkthrough. It does not describe a deployed monitoring service.

## Define the decision boundary

Use a specific question: “Should the sample team request an alternate route review for a component delivery?”

Choose a fictional supplier, corridor, and delivery window. Avoid adding real customers, personal information, or confidential business records to the demo.

## Prepare three kinds of evidence

- An initial notice that suggests a possible change.
- A dependency record that might connect the change to the business.
- A later update that either supports or weakens that connection.

Give each record a stable synthetic identifier. Record event time separately from the time it becomes available in the exercise.

## Include a competing explanation

A supplier delay might result from an internal scheduling change rather than the regional event. Introduce a fictional update that raises that possibility.

The exercise should make it possible to preserve two explanations until evidence distinguishes them. A visually compelling relationship diagram should not force an early conclusion.

## Evaluate the handoff

Ask a second reviewer to identify the observation, the inferred impact, the missing evidence, and the next action using only the sample brief.

If those answers require an oral explanation, revise the briefing content or hierarchy. The aim is inspectable reasoning, not the number of alerts or panels on screen.

## State the implementation boundary

Kojima supplies an interface template and editorial examples. A production service would need separately implemented data ingestion, identity and authorization, source governance, review workflows, and operational testing.

Successful completion of this exercise demonstrates that a sample narrative is understandable. It does not establish analytical accuracy, security readiness, or production capability.
